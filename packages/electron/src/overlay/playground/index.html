ChessRay overlay — UI playground

Three layout directions to choose from. Each is a static mock with the same data.
→ Refactor proposals (3 new directions) — preserve draggable multi-section + compact mode

Studio

Left icon-rail acts as a section switcher. One section visible in the main pane at a time. Best when you have a lot of features and want a focused workspace.

+ scales to many sections · − one-thing-at-a-time

Cards

A polished refinement of today's split-layout. Sections live as draggable cards in a grid; menu bar covers every action. Multiple sections visible at once.

+ everything visible · − can clutter

HUD

Single-column, minimal-chrome layout. Board + side eval bar + lines always visible; tuning is a slide-down drawer. Smallest footprint on screen.

+ tiny footprint · − tuning hidden

Arrow styles

Side-by-side alternatives to the current gradient arrow: solid flat, outlined, neon, tapered, chevron, minimal, double-stroke. Tune board brightness and scale live.

+ direct comparison · + live controls
All variants share the same proposed IA: Position · Analysis · Tuning · Tools · Diagnostics, with top-bar menus covering Sections, Display, Mode, Tools.
These are visual mockups for direction-picking, not functional prototypes.
Interactive: menu popovers, tabs, sliders, drawer (HUD), section switch (Studio), compact toggle.
Not wired: panel drag/resize, section drag, hide/zoom/close — these all already exist in split-layout.ts and would be reused once you pick a direction.
